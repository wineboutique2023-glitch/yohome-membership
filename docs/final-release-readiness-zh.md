## 本轮上线安全修复

- 收据函数根据认证身份及数据库 CRM 角色放行，只接受会员 ID。收件人、金额、PDF 和条款来源由服务端决定。未经服务端确认无法通过 CRM RPC 或直接 Owner 表操作改成已发送。预览发信必须绑定测试邮箱并配置独立发信凭据。默认发信关闭。
- 收据提供商请求使用按会员 ID 的幂等键。若供应商已接收、写状态失败，先依据供应商日志核对，再决定是否重试。预览用途不得共享生产发信凭据。
- 预览构建仅接受 `ncmgkslwzoxozsmmdqli.supabase.co`。测试数据库已增加精确 $50 的验收服务。Vercel 连接仍返回 404，实际生产分支、四项变量及托管运行尚未核验。

## 最少需要管理员操作的事项

1. **Vercel → 项目 yohome-membership-pi7k → Settings → Environments → Production → Branch Tracking**，提供真实分支名和项目 Dashboard 链接。**Settings → Environment Variables → Preview** 核对四项变量。Vercel 连接需能访问实际项目所属的 Team。可在已登录的浏览器核验，勿把 Vercel Token 粘贴到聊天。确认可以定向 Preview 后，优先使用直接 Preview 部署方式，避免为验收推送生产分支。
2. **Supabase 测试库 → Authentication → Users → Add user**，创建 Owner 和 Staff 测试用户，提供测试 UID 与角色以便仅在测试库设置角色。为实物扫描测试准备带前导零的卡。按终端预览指南操作，重点观察查卡 Enter、换卡确认页、旧余额和新卡余额。
3. **Supabase 测试库 → Edge Functions → Secrets**，若要验收真实收件，配置独立测试用 `RESEND_API_KEY`、`FROM_EMAIL`、`MEMBERSHIP_TEST_RECIPIENT`，以及要验收的服务器条款 URL `MEMBERSHIP_TERMS_PDF_URL`。用指定测试邮箱注册模拟会员，在收件箱核对收件人与附件。生产模式开关仅在正式获批的生产环境配置。
4. **Supabase 生产库 → Connect → Session pooler**。管理员在可信电脑按 [备份与恢复指南](final-preflight-zh.md) 导出角色、结构和数据到加密目录；在独立的本机恢复环境实际还原。记录导出时的表行数、角色、策略和函数清单、SHA-256、恢复起止时间以及核验结果。不得上传脱敏前的数据或凭据。生产快照未生成或恢复成功前，本步骤保持未完成。只读核对当时为 57 条会员、218 条 Checkout、12 条服务、7 条人员及 1 条设置，最终以正式快照时核对为准。

## 生产切换顺序与回退

1. Owner 确认可恢复备份、隔离恢复演练、托管 Preview 全流程和邮件验收，批准维护窗口与生产变更。值班人员暂停会员登记、结账、发卡、兑卡和发信，记录切换前行数及最后一笔业务标识。
2. 发布管理员再次核对 Vercel 目标及 Supabase 项目 ID。按序迁移独立新增结构、CRM 授权、旧行为兼容和服务端收据状态；协调部署安全收据函数和 Auth 前端，避免业务在旧匿名前端与新 RLS 混用时继续写入。验证后再恢复操作。
3. 复核 Owner/Staff 及匿名访问、既有会员历史、工资利润、售卡兑卡和对账。收到异常先停相关写入，保留所有迁移、结账和礼券日志；切换到经过验收、与新权限及收据协议相容的前端或维护页。运营变更可按审批关闭礼券入口并暂停柜台业务。若涉及账本异常，停止礼券写入并恢复备份到另一个环境对账，生产写回需专项批准。公开匿名权限不作为回退手段。
4. **共享临床数据独立应急处理。** 诊所 Owner 负责指定业务负责人并批准短窗口。Supabase 管理员先梳理三张表和使用应用、留存备份及脱敏访问日志。应用负责人先完成治疗师及公开 Intake 的受保护路径和回归，再由数据库管理员协调撤销临床表匿名访问。诊所业务负责人复核真实签到、SOAP 和自动开票。详细范围见 [临床表修复计划](clinical-production-access-plan.md)。该任务不因礼券 Preview 等待而推迟评估。
